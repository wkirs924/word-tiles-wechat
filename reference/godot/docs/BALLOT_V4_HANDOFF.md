# v4 两步投票与电子数字 · 2026-09-25

> 投票规则与视觉设计仍有效。2026-09-26 已将 main 的判断草稿迁到 game_controller，布局迁到 ballot_view/result_view/lobby_screens；当前文件接口见 [重构交接](PRESENTATION_REFACTOR.md)。下面文件表为本次设计形成时的记录。

本轮按照用户截图修改投票流程、数字风格和准备开局页面。

## 当前流程
每位投票者先看到认可/反对。无图：直接提交 approve + rating=0；有图：本人的选择先存为本地草稿，转场到 0–3 评分页，点击分数后原子提交。本地评分页可返回判断页，没有半张票进入主机。其他人看不到临时判断；交接清除草稿。带图时无论认可还是反对，均填写评分；沿用通过后取全部三人平均、否决零分的规则。未提交者的等待与已提交者的状态使用文字说明，不摆放灰色无效按钮。

这不是“先收全桌三张票再统一评分”的新核心阶段。核心仍是 AWAIT_VOTES，接口仍为 SUBMIT_VOTE；改变的是本地步骤与无图计分约束。规则版本为 word-tiles-4。v3 会话/回放不能直接按 v4 解释，使用上一份 Git 版本即可回看旧规则。

## 视觉
- digital_number.gd 是本项目绘制的分段格子数字，不引入外部字体或字体授权依赖。支持 0–9、小数点、负号，评分按钮、本局分数与累计总分使用同一组件。
- 字形使用矢量绘制，颜色来自 catalog.theme.digital，可在网页「主题颜色 → 电子数字发光色」编辑。
- 中文标题/提示仍使用素材表中的字体角色；数字字形本身由组件定义，系统字体设置不会改变分段数字。
- 判断与评分用独立 motion_key，进入评分时淡入上移。沿用跳过动画和简化动效。
- 等待发牌改为居中的四席准备卡片；菜单、交接、准备页均有入场，发牌时手牌从中央展开；状态不等待动画。

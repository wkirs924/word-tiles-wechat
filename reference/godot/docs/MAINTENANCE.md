# 维护、验收与后续里程碑

## 本次范围

M1 是纯逻辑核心与 headless 测试。为证明可集成性，一并提供投影、最小本地主机、多局会话和重连接口的纯数据实现；这不等于已经完成本地轮流界面、联机、数据库或 Steam 集成。

当前 word-tiles-4 将表情包 key 并入出句，其他三人先判断，带图再评分并原子提交，无图直接提交 rating=0。核心负责平均分与直接清算，M4 负责图片、选择界面、搜索、内容工作台和字体配置。声调选择仅做数据记录与结构校验，没有拼音推断或音频实现。

## 开发约定

- 文件与函数用 snake_case，命令/事件/phase 用 UPPER_SNAKE_CASE。下划线函数仅模块内部调用。新增对外行为先补协议，规则只由核心计算。
- main 只做装配和页面路由；意图/草稿放 GameController，页面只发信号。投票、结算、表情搜索和通知已有独立模块，按 [模块表](PRESENTATION_REFACTOR.md) 扩展，不增加 main 的转发壳或直接访问另一个模块的私有字段。
- 可调数值写入 Rules.defaults 并经过 validate；配置冻结在会话中。不要另建一份 UI 计分表或硬编码按钮合法性作为规则裁判。
- 新规则同时改 RULES、CONTRACTS 和相关分支测试；若会改变旧命令解释，更新 rules_version 并设计兼容方案。
- 动作校验失败不能产生局内副作用；回执账本记录失败是应用层审计，不能误当作计分成功。日志不可发给客户端。
- 对 JSON 数字先校验整数性/范围，不能先 int() 截断再当合法输入；生成 ID 时取整避免 JSON 读回后的 `.0`。
- 保存格式必须有版本；不可向状态加入 Resource、Node、Callable、文件路径或平台对象。迁移使用显式纯数据函数，未来存储适配器负责 IO。
- 素材表（catalog.json）是表现层配置，不属于牌局状态。改数据模型、固定 key 或字体角色时必须同时改 `server.py:validate_catalog`、`presentation/content_store.gd:valid_catalog` 和 `tools/content_editor/editor.js` 的渲染/归一化；界面文案分组常量 `UI_GROUPS` 要跟游戏页面用法同步。细节见 [CONTENT_EDITOR.md](CONTENT_EDITOR.md)。
- 字体只接受系统已安装字体名（`SystemFont`）；新增角色要同步 `server.py:FONT_ROLES`、`content_store.gd` 允许列表、`editor.js:FONT_ROLES`，并在对应控件上覆盖。字体缺失由系统回退，不能让坏配置导致游戏拒载或崩溃。
- 用有业务意义的回归测试验证 bug；不要写只逐行镜像实现的测试。测试模拟器只是固定动作序列，不是 AI 功能。

## 测试执行

Windows 推荐 README 中的 scripts/test.ps1。它启动隐藏的 headless 进程，收集 stdout/stderr，检查退出码、SCRIPT ERROR、FAIL 和最终计数；120 秒是操作系统进程等待上限。Godot `--quit-after 120` 表示 120 次主循环迭代，不代表 120 秒，两者不要混淆。

直接执行 tests/run_tests.gd 可验证核心；CI 仍需同时检查输出，因为 GDScript 某个测试函数运行时错误可能提前返回。测试入口和完整测试脚本都不访问任何业务网络服务。发生环境级引擎初始化警告时，记录原文，区别于测试断言/脚本错误，不能隐藏失败断言。

素材工作台单独运行 `python tools/content_editor/test_server.py`（当前 15 组）。改动 `server.py`、素材表结构或编辑器校验时必须与 Godot 回归一起通过；字体字段的边界校验在 `validate_catalog`，新增规则建议补进该测试文件。

表现层可先运行 `tests/run_ui_tests.gd`，提交前仍跑完整入口。`python -m unittest discover -s tests -p test_project_integrity.py` 检查素材文案/网页分组、图片映射、模块依赖和本地文档链接，防止删除旧交互后留下无效配置。测试不能只看行数变少；交接隐私、失败后保留草稿、滚动/焦点、动画销毁都属于回归范围。

## 风险与上线前工作

**性能。** 当前每次动作深拷贝会话，并保存整个命令日志与回执；适合四人、默认四局的原型。长时间手动续局或大量失败命令会扩大内存与复制开销。M5 需在适配器做消息大小限制、身份级限速；长期会话需设计日志分段/检查点和保持幂等语义的回执存储，不能直接删除旧 ID 后允许重放计分。尚未给出大型会话吞吐保证。

**可信主机。** P2P 玩家主机能看到完整牌墙与手牌；投影保护普通客户端，不防主机修改程序作弊。主机离线现在只能等待/终止，没有故障转移承诺。

**许可证。** 当前代码没有引入第三方麻将实现或资源；候选仅供机制参考。以后复制任何实现时，固定提交、保留许可证及版权通知，并单独核对字体、音效、图片和插件许可证。GPL/AGPL 不纳入这次可复用候选。项目本身未擅自选择对外分发许可证，由权利人决定。

**UGC 与版权。** 工坊接入应提供举报、按作者/作品屏蔽、审核队列、下架记录和申诉处理；可共享内容采用先审后发策略，官方包优先自制或明确授权素材。本地导入默认不自动上传，分享时单独经过授权与审核流程。只存 key 仅是技术解耦，不等于消除版权责任。是否允许发布某素材应依据实际权利与平台政策核查，不宣称缺少某个按钮就必然被下架。

**语音授权。** 接入演员录音或第三方 TTS 前核对商业使用、再分发、合成/拼接、地域期限及音色使用授权。运行时 TTS 的 API 许可不自动等于任意音色可商用。音频仅影响表现，不影响得分与胜负。

**内容与多平台。** 外部字库负责单字、本音、多音字和内容版本的一致性；M1 不判断一个 Unicode 字符是不是合格汉字。产品文案与资源 key 外置，Windows 先验证，macOS/Linux 及导出构建需要后续真实设备/CI 验证。

# M2：投影与本地会话

> 历史验收记录；当前玩法与协议以 [RULES.md](RULES.md) 和 [CONTRACTS.md](CONTRACTS.md) 的 word-tiles-3 为准。

已实现无界面的 LocalTable，完成本地操作者交接控制；没有新增 UI、联网或 Steam 功能。

| 验收项 | 状态 |
|---|---|
| 每人独立状态/事件投影 | 已有实现与测试，继续沿用 |
| 本地当前操作者绑定 | 已实现，submit 不接受客户端 actor 参数 |
| 开始交接立即隐藏旧视图 | 已实现，返回 screen=HANDOFF、view=null、空 events |
| 确认交接才读取新视图 | 已实现，从权威主机重新生成，不恢复客户端旧数据 |
| 交接期间不能操作 | 已实现；无效座位请求也会先清除旧身份 |
| 投票、评分与跨局交接 | 完整四人集成测试覆盖 |
| 保留 M1 规则和测试 | 总测试入口同时运行 M1 与 M2 |

新入口是 application/local_table.gd，测试为 tests/test_local_table.gd，已经接入 tests/run_tests.gd。控制器只保存当前/待确认玩家 ID，不复制游戏状态，不调用核心私有函数，不实现重复的规则判断。

交接顺序：可信本地控制器选择目标座位 → begin_handoff → 表现层清除上一位玩家的牌和动画并显示交接屏 → 接手者确认 → confirm_handoff → 渲染新投影。切换座位不自动执行游戏动作；投票和评分仍由每个人明确提交。M3 必须执行清屏要求，M2 无法擦除外部组件自行保留的旧引用或屏幕像素。

这是同一设备上的可信轮流操作，不是身份认证；未来联网不能让客户端任意调用交接来冒充座位。网络继续由适配器绑定连接身份。

集成测试覆盖：初始化隐藏、交接屏数据为空、确认后的本人手牌、遮挡期间拒绝提交、三名玩家依次投票、胡牌后的三名评分者交接、累计分、新局重新发牌、伪造 actor 拒绝、手动遮挡、无效目标、主机结束本局。实际运行输出见 [M2_TEST_OUTPUT.txt](M2_TEST_OUTPUT.txt)。

M1 历史验收记录保留不改；本文件记录在其基础上新增的 M2。界面与动画继续留在 M3。

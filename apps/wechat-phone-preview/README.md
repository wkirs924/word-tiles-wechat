# 手机扫码试玩包

这是 `scripts/build-wechat-phone-preview.py` 从 `../wechat-preview` 生成的独立微信小游戏项目。当前版本使用 **小主包 + 按需动图分包**：保留 74 张静图、59 组动图，单帧最长边最高 288 像素、最多 32 帧，目标采样 12 fps，JPEG 只从原始 GIF 编码一次。主包小于 4 MB，包含全部分包的总量另行计数，具体数据见 `../../docs/PERFORMANCE_BUILD.json`。本轮仅本地构建，尚未上传；以前的预览码/体验码不包含本轮改动。上次上传记录保留于 `../../docs/STATUS.md`。

在项目根目录重新生成预览二维码：

```powershell
& 'D:\微信web开发者工具\cli.bat' preview --project 'E:\dev\word-tiles-wechat\apps\wechat-phone-preview' --qr-format image --qr-output 'E:\dev\word-tiles-wechat\phone-preview-qr-wifi-table.png' --info-output 'E:\dev\word-tiles-wechat\phone-preview-wifi-table-info.json'
```

手机上用**微信扫一扫**该二维码。单机试玩仍可在一台手机上轮流交接；“同 Wi-Fi 联机”入口改为**一台手机当房主、其他手机加入**，不需要电脑运行服务。两到四台手机先连同一个 Wi-Fi，房主点“创建房间”，把屏幕上的 6 位房间号复制给其他玩家；客人输入房间号，小游戏会在局域网内自动发现房主。旧版 `IP:端口/密钥` 房间号仍兼容，客人各自点准备，房主点开始。每台手机只显示自己的手牌，房主手机运行权威规则并分发视图。

当房间只有两台手机时，游戏仍按四个座位运行：房主控制东、西两个位置，加入者控制南、北两个位置。轮到某个位置时，对应手机会显示该位置的手牌；投票阶段可点“切换位置”依次替自己的两个位置投票。

如果第二台手机提示“暂无体验权限”，这是微信账号权限拦截：用小游戏管理员账号进入微信公众平台，在“成员管理/项目成员”中把第二个微信号加入“体验成员”，然后在“版本管理”中把已上传版本设为体验版，再使用体验版二维码扫码。开发者工具的“预览”二维码通常只给当前开发者账号使用；加成员后仍扫码旧预览码不会自动获得权限。

房主必须保持微信小游戏在前台；房主退出或系统杀进程后，房间和当前牌局会结束。客人短暂掉线可以使用原手机重连；玩家重连令牌只保存在本机。不同 Wi-Fi、访客网络隔离或手机禁止局域网访问时无法互通。当前双手机实机连接尚待验收，四手机端到端已用模拟 UDP 测试；二维码成功上传不等于真机联网成功。

真机反馈曾出现“当前微信版本缺少安全随机数接口”。现优先使用 `wx.getRandomValues`，没有时改用标准 `crypto.getRandomValues`，两者都不可用才用 `Math.random` 混合时间生成局域网试玩用房间密钥和重连令牌。最后一种来源不具备密码学安全性，因此这套离线房间只适合可信的同 Wi-Fi 试玩。

二维码成功生成只证明开发者工具编译、上传成功；手机实际启动、触摸和动画表现仍需扫码验证。修改源预览后在项目根目录运行 `scripts/build-wechat-phone-preview.py`，再用开发者工具重新预览；不要手改此目录内的代码或资源。


## 重建与性能

只改游戏代码后执行：`python scripts/build-wechat-phone-preview.py`。更新原始 GIF 后先执行 `python scripts/build-preview-content.py --animations-only`，再构建手机包。构建脚本会复制代码、划分动图分包、设置 `minified=true`，只清理旧生成清单中已不再使用的资源。包体预算：主包 3,800,000 bytes；每个分包 3,500,000 bytes；总包 19,000,000 bytes。实际上传限制与压缩结果仍以开发者工具为准。

点按时加载所需动画分包并循环播放，松手后继续；点另一张切换。下载中保留静图并显示提示，失败后可稍后再点。后台暂停动图并释放图片，前台恢复；收到内存告警时释放缓存。原始 GIF 已有的模糊、少色和文字细节缺失不会被重建恢复。诊断接口：`GameGlobal.WordTilesPerformance.snapshot()`（不包含玩家数据）。

# 自定义表情：相册导入与同 Wi-Fi 房间共享

## 本版范围

2026-09-30 按用户选择实现：手机相册入口；名称与必填关键词；上传者保存在本机“我的表情”；添加后进入当前同 Wi-Fi 房间的共享表情库，所有玩家接收后都能搜索、选择、出句和观看动画。沿用四人试玩的表情造句/投票/评分界面与搜索排序规则。普通浏览器四人试玩可选本地文件并保存在 IndexedDB；浏览器 Node HTTP/WS 房间尚不提供自定义文件共享。

资源通过房主手机转发，不需要云服务器、域名、对象存储或新的上传组件。房主须保持前台运行。未发布到微信、未上传到任何公共服务。

## 使用

1. 选择至少两张字牌，打开“表情造句”，点击“＋ 添加表情”。
2. 从相册选择原图，查看预览，输入 1–24 字名称、1–5 个关键词（每个最多 12 字，空格、中文或英文逗号分隔）。
3. 本地试玩点击“保存到我的表情”；Wi-Fi 房间内点击“保存并分享到房间”。
4. “我的表情”显示本机收藏；“房间表情”显示当前房间共享库。选用以前收藏但未分享的表情，会先分享到房间再选择。
5. 接收中的卡片不能选择；所选表情尚未全部送达时，“提交句子”显示“表情同步中”。同步完成后恢复提交，房主也会检查资源白名单与全体接收状态。
6. GIF 在选择页点按一次后持续播放；在投票/评分轮播中自动播放当前自定义 GIF。切换动画时只保留一个完整动画图集，后台和内存告警释放运行时图像。
7. “我的表情”卡片可以删除。删除本机收藏保留当前房间的独立副本；退出房间清理共享副本。下次进新房，从“我的表情”重新选择即可分享。

“我的表情”保存在小游戏用户目录；浏览器保存在该来源的 IndexedDB。清除应用/微信缓存、卸载或更换手机后不能保证保留；没有账号云同步。

## 约束与预算

- GIF / JPG / PNG，按文件内容识别格式；相册使用 `wx.chooseImage({sourceType: ['album'], sizeType: ['original']})`，不主动压缩 GIF 成静图。浏览器使用本地文件选择器。
- 单文件 16 B–2 MiB，宽高各不超过 1024 像素。GIF 最多 30 秒、300 源帧、累计 5000 万源像素；超限明确提示，不上传、不登记。相册如果返回的已经是静图，只能按实际静图导入，GIF 原图保留情况待 Android/iOS 真机确认。
- 私有库最多 50 张 / 20 MiB；单房共享库最多 24 张 / 20 MiB。退出房间/下次启动清理房间临时文件；启动清理本模块目录里的遗留写入临时文件。
- 原始编码文件在运行时读写和传输，不写入 `content.js` 或小游戏代码包。新增三份 JS 由手机构建脚本复制；主包仍受 3.8 MB 本地预算门槛控制，实测见 `PERFORMANCE_BUILD.json`。
- GIF 在客户端有界解码，按原时间轴均匀采样，最长边最多 256 像素，最多 32 个显示帧，通常目标约 12 fps（长动画受 32 帧上限影响；很短的两帧动画保留两帧）。保持完整循环时长，不宣称真机帧率。支持透明色、帧局部更新、disposal 2/3、交错行与 LZW；不支持 GIF 文字绘制扩展。
- 缩略图最多保留 16 个 256 像素画布；完整自定义动画只保留一个，显示图集 RGBA 最多约 8 MiB。解码期间另有原始画布/恢复帧等临时内存，不把显示图集预算当作进程峰值内存。

## 文件与协议

- `apps/wechat-preview/game.js`：共用筛选/添加/预览/输入/保存/删除界面，自定义图集绘制、出句同步状态。
- `gif-codec.js`：无平台依赖的 GIF 解析和 LZW 解码；每处理三帧让出一次事件循环，保留所有源帧的合成顺序后采样。
- `custom-memes.js`：格式/尺寸/标签校验、SHA-256 资源地址、微信文件持久化、浏览器 IndexedDB、缩略图与单活动动画缓存。
- `lan-assets.js`：独立文件通道。`ASSET_BEGIN / CHUNK / END / ACK / ERROR / GET / HAVE` 绑定当前房间和已经入房的发送端点。8 KiB base64 块，逐块确认、超时有限重试，单客户端串行读取和发送文件，避免提前把整个库为每位接收者都读进内存；接收并校验完才进入资源库。校验大小、真实格式、尺寸、GIF 限制及文件+标题+关键词的 SHA-256 地址；远端路径不能进入协议。
- `lan-client.js`：房主独立动态资源白名单；快照仅携带最多 24 项元数据与接收者列表，游戏命令只携带资源键。新入房/重连后按目录请求缺失资源。未完成共享的资源不能出句。状态传输保持 400 字符分片，上限调整为 384 片，以容纳带自定义长资源键的单局句子记录；最多 16 个部分组装包，过期清理。
- `scripts/build-wechat-phone-preview.py`：同步以上源码到生成手机包；不手改生成目录。

不改字牌、投票、表情计分、三票齐后结算和否决后弃牌的规则核心。

## 待真机验收

本轮执行语法检查、差异格式检查和手机包构建；未新增或运行自动测试，未做真机验收。

1. 两手机同 Wi-Fi 建房，在表情选择中导入 GIF，填关键词，确认另一台“房间表情”收到并可搜索/选用。
2. 导入 GIF 出句，其他操控者投票/评分期间确认图像连续播放；检查透明、局部更新、disposal 2/3 和交错 GIF。
3. 退出小游戏重进，检查上传者“我的表情”仍在；新房重新选用时自动分享。
4. 第三/第四台新加入、原手机断线重进，检查目录补传、未完成时按钮禁用、完成后恢复。
5. 接收期间退出房间，检查没有迟到的资源登记；丢包/后台/断网时检查有限重试和错误提示，回到前台重试后恢复。
6. 拒绝相册选择或取消，不创建表情；空关键词、超 2 MiB、超过尺寸、GIF 时间/帧/工作量超限应提示且不影响牌局。
7. 删除收藏后当前房间已有出句仍可播放；退出清理共享副本，换新房不会显示旧房共享库。

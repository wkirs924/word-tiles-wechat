# 验证、运行与交付

## 测试分层

1. 纯规则：正常动作、非法动作、牌守恒、计分、隐私、幂等、回放。
2. 对照：固定输入让 Godot 与 TS 分别执行，对比权威状态/回执/事件/各人视图。
3. 网络：四客户端、并发提交、断线、重复请求、持久化崩溃窗口。
4. 客户端：安全区、触摸排序、键盘、等待状态、资源失败。
5. 微信真机：开发者工具仅为一层，Android/iOS 分别记录。

## 核心必须覆盖

| 场景 | 预期 |
|---|---|
| 固定 seed=42、136 张 | 洗牌/骰子/庄家/手牌可与原实现一致 |
| 同一汉字多张物理牌 | 不混淆 id；重复同一 id 拒绝 |
| 造句无图 | 不显示评分步骤；核心拒绝非零 rating |
| 有图第三票 | 通过时包括反对者分数；只结算一次 |
| 两票已赞成、第三票未到 | 仍等待，无提前移牌/计分 |
| 否决 | 旧分保留，本次零分，强制弃一张 |
| 最后手牌出句通过 | 胡与结算原子发生 |
| 单张弃空 | 不胡 |
| 墙剩最后一张 | 摸后仍正常动作，下次摸才流局 |
| 跨局累计并列 | 精确分子排名 1,2,2,4 |
| END_GAME 中止 | 无最终累计，不消耗计划完成局数 |
| 最后一票同 ID 重试 | 原回执，无新 revision/结算 |
| 同 ID 换 payload | COMMAND_ID_REUSED |
| 拒绝再重试 | 相同拒绝回执，牌局保持不变 |
| 非法 actor/未知字段 | 拒绝，无越权 |
| 字符串特殊键 | __proto__/constructor 等不污染原型 |
| 四人投影 | 他人手牌、wall、seed、逐人票不可见 |
| 回放所有已记录命令 | 最终状态/计分一致 |

## 网络故障矩阵

- 发出前断线：恢复后确认是否仍可执行。
- 服务器已提交、ACK 丢失：同 ID 重发不重复执行。
- 三人同时投票：每票按 proposal 校验，不能因 revision 改变误拒。
- 保存失败：无成功 ACK、无内存状态超前。
- 提交后进程退出：重启恢复已提交状态和幂等账本。
- 同账号双连接：新连接替换旧连接；旧 generation 动作拒绝。
- 房主掉线：牌局等待，不将权威状态交给其他手机。
- 切后台到微信聊天再回来：重连快照、清理过期草稿，无重复动画。
- 动画加载失败：占位展示，状态继续同步，不能卡在动画回调。

## 命令与证据

bootstrap: `powershell -ExecutionPolicy Bypass -File scripts/test.ps1`。

M1 之后测试入口应包含全部新测试。M2 新增独立集成测试命令和服务器启动命令；M3 写 Cocos 编辑器/构建命令；命令必须在实际环境运行后再标记 verified。

测试执行输出可存入 `artifacts/verification`；黄金样本生成器、输入和摘要要一同保存。二进制构建、缓存和凭据不要加入源码。TypeScript 静态检查应使用固定依赖和 lockfile；Node TS 类型擦除不提供静态类型证明。

# 决策、边界及风险

## 已决定

- 微信小游戏，Cocos + TS 重建；旧工程作为规则参考。
- 四人好友房优先，横屏优先，服务端权威，单实例起步。
- 沿用 word-tiles-4，不顺手更改投票/计分/超时规则。
- 首版少量固定素材；原大图目录不进入初始代码包。
- M1 先闭环规则，M2 先四客户端联调，再接手机视觉。

## 默认产品决策（可调整但必须记录）

- 牌局中断线不判负、不代打、不自动投赞成；房主可结束本局。
- 房主显式离开活动牌局时提示将中止本局，确认后服务端执行 END_GAME，再离房；不实现房主迁移。房主只是暂时断网则保留席位等待。
- 全员离线房间保留 24 小时（工程默认，可配置）；清理时标记过期中止，不把未完成局计入成绩。清理由应用层可信操作完成，不将系统时间塞入 reducer。
- 用户主动退出与网络暂断分开处理；不让客户端断开连接自动等价于退房。
- 同一账号同时只控制一席；重复登录替换连接。房间码不是认证凭证。
- 默认昵称/席位头像先可用，不强制索取个人头像昵称权限。

## 技术风险和处理

1. TypeScript 翻译出微小规则偏差：旧测试矩阵 + Godot 实际输出对照，尤其洗牌、Unicode、负分和 thirds。
2. 过度相信类型系统：所有网络数据运行时校验，核心对非法数据也有行为测试。
3. 服务器房主越权：网络意图与可信核心开局分离，不开放指定 seed/wall 或替人摸牌。
4. SQLite/内存不一致：先事务提交，再更新内存并推送；失败注入测试。
5. 全状态复制/历史账本增长：MVP 限制会话生命周期；后续压缩需要保留幂等和回放语义，不盲目删回执。
6. 引擎导入共享模块：机械生成客户端代码副本、hash 校验；不能两份 core 各改各的。
7. 动图内存与 GPU 兼容：预处理、按需解码、缓存预算、双端真机测量。
8. 资源版本漂移：每房间冻结版本；新版本客户端可读旧房间版本或明确拒绝进入。
9. 只有开发者工具截图：禁止当作微信手机验收证据。

## 发布边界

本交接聚焦技术实现，不把资质办理/商业化列入首版功能。公开上线前仍需核验主体、类目、备案、隐私、内容和素材来源；不得宣称本交接已经完成这些事项。
